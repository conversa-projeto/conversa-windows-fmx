> A coluna **FMX** descreve o app **atual**. O andamento da nova base (se aprovada) é registrado no `TODO.md`; esta matriz é atualizada a cada etapa (ver "Revisão periódica" no `TODO.md`).

## Legenda

| Símbolo | Significado no FMX **atual** |
|---|---|
| ✅ | Existe e funciona contra o servidor atual |
| 🟡 | Existe parcialmente ou com defeito relevante |
| 🔴 | Existe, mas **quebra contra o servidor atual** ou tem defeito crítico |
| ⬜ | Não existe |
| ➖ | Não se aplica literalmente ao desktop; precisa de **adaptação** (coluna "Adaptação Windows") |

A coluna **Fase** indica em que fase do plano (doc 07) a funcionalidade entra:

| Fase | Escopo |
|---|---|
| F0 | Fundação (projeto Win64, HTTP, tempo real, sessão, cache, barramento, design) |
| F1 | Sessão, conversas, contatos e presença |
| F2 | Mensagens: núcleo |
| F3 | Anexos e mídia |
| F4 | Ações sobre mensagens |
| F5 | Notificações e integração com o Windows |
| F6 | Chamadas |
| F7 | Atividades, pesquisa, perfil e configurações |
| F8 | Extras (SIP, janela de conversa separada, cores, atualização automática) |

**Prio:** P0 = obrigatório para o cliente funcionar contra o servidor atual · P1 = paridade essencial · P2 = paridade completa · P3 = opcional/avaliar.

**No desktop, quase tudo do web vale literalmente:** clique direito, passar o mouse, arrastar e soltar, colar, atalhos de teclado e janelas separadas existem no Windows (doc 03 §7). Os poucos ➖ são o que depende de navegador (permissões do navegador, *service worker*/FCM, conexão lenta) ou de toque.
